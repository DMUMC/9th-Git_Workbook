# Git이란 무엇이고 왜 사용해야 할까요?

Git은 파일의 변경 사항을 추적하고 여러 사용자 간에 파일들의 작업들을 조율하기 위한 **분산 버전 관리 시스템(DVCS)**입니다. 정확힌 언제 파일을 수정했는 지, 그 때 파일 내에서 어떠한 변화가 있었는 지 기록해주기 때문에 파일을 여러 개 저장하지 않아도 된다.

---

## 1. Git의 핵심 개념

* **버전 관리**: Git은 파일의 변화를 기록해 여러 개의 복사본을 만들 필요 없이 깔끔하게 이력을 관리합니다.
* **분산 관리**: 각 개발자는 자신의 컴퓨터(로컬)에 전체 코드 이력을 가지고 있으며, 깃허브(GitHub) 같은 원격 저장소와 동기화하며 협업합니다.
* **저장소(Repository)**: 모든 파일과 그 기록이 저장되는 공간으로, 로컬 저장소와 원격 저장소로 나뉩니다.

---

## 2. Git의 주요 명령어

### 기본 워크플로우

1.  **`git clone [URL]`**: 원격 저장소의 코드를 내 컴퓨터로 가져옵니다.
2.  **`git status`**: 현재 파일 상태를 확인합니다.
3.  **`git add [파일명]`** 또는 **`git add .`**: 변경된 파일을 커밋할 준비(스테이징) 상태로 만듭니다.
4.  **`git commit -m "[메시지]"`**: 스테이징된 파일을 로컬 저장소에 기록합니다.
5.  **`git push origin [브랜치 이름]`**: 로컬 저장소의 기록을 원격 저장소로 보냅니다.

### 브랜치 관리

* **`git branch [새로운 브랜치 이름]`**: 새로운 브랜치를 만듭니다.
* **`git switch [브랜치 이름]`**: 특정 브랜치로 이동합니다. (Git 2.23 이후 권장)
* **`git merge [브랜치 이름]`**: 다른 브랜치의 내용을 현재 브랜치로 합칩니다.

---

## 3. Git을 활용한 협업

* **브랜치(Branch)** 
    * 서로 영향을 주지 않고 독립적으로 작업하는 공간입니다. 보통 기능별로 브랜치를 나누어 개발합니다.

* **.gitignore** 
    * Git이 특정 파일(예: 민감한 정보, 불필요한 파일)을 추적하지 않도록 설정하는 파일입니다.

* **이슈(Issue)와 풀 리퀘스트(Pull Request, PR)** 
    * **이슈(Issue)**: 버그 수정, 기능 구현 등 처리해야 할 작업 목표를 기록하는 도구입니다.
    * **풀 리퀘스트(PR)**: 내 작업 브랜치의 내용을 메인 브랜치로 병합해달라고 요청하는 기능입니다. 이를 통해 팀원들이 코드를 검토(리뷰)하고 논의할 수 있습니다.
