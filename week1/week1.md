# Git이란?

> 파일의 변경 사항을 추적하고 여러 사용자 간에 해당 파일들의 작업들을 조율하기 위한 **분산 버전 관리 시스템**

### 1. 파일의 변경 사항을 추적

-   하나의 파일 안에서 변경된 모든 **이력(history)을 기록하고 추적**
-   언제, 어떤 내용이 수정되었는지 로그가 남기 때문에 **특정 시점의 버전으로 쉽게 되돌아갈 수 있음.**
-   여러 개의 파일을 저장하지 않아 불필요한 **저장 공간 낭비를 막을 수 있음.**

### 2. 여러 사용자 간의 협업 조율

Git은 원격 저장소, 대표적으로 **Github**를 활용

-   **로컬(Local):** 내 컴퓨터
-   **원격(Remote):** Github와 같은 인터넷상의 저장소

모든 팀원이 **동일한 프로젝트와 변경 이력을 공유**

### 3. 분산 버전 관리 시스템 (DVCS)

-   **버전(Version):** 파일이 수정되고 기록되는 특정 시점.
-   **버전 관리(Version Control):** 이러한 버전들을 체계적으로 관리하는 것.
-   **분산(Distributed):** 중앙 서버뿐만 아니라, **모든 사용자의 로컬 컴퓨터에 전체 저장소가 복제되어 저장**되는 방식.

# Git에서의 파일 관리

### 1. Working Directory

내가 현재 직접 파일을 수정하고 생성하는 프로젝트 폴더.

-   Working Directory에 있는 파일의 변경사항은 기본적으로 Git이 추적.
-   **.gitignore 파일**: 보안 정보나 개인 설정 등 **Git의 추적에서 제외하고 싶은 파일** 을 기록하는 파일.

### 2. Staging Area

Working Directory에서 변경된 파일들 중, 저장소에 기록할 것들만 선별하여 올려두는 임시 공간.

-   **상태**:`unmodified`(변경 없음), `modified`(변경됨), `staged`(스테이지됨)
-   **add**: `modified` 상태의 파일을 `staged` 상태로 만들어 **Staging Area로 옮기는 과정**. 


### 3. Local Repository

Staging Area에 준비된 파일의 변경사항을 **버전(하나의 체크포인트)**으로 만들어 최종 기록하는 곳.

-   **commit**: Staging Area에 있는 파일들의 변경 이력을 **하나의 버전으로 저장**하는 명령어.
-   **push**: `commit`을 통해 로컬 저장소에 기록된 변경 내역을 **원격 저장소(Github)에 업로드**하는 명령어.

# Git의 사용법

### 1. 원격 저장소 생성 및 로컬 연결

1.  **Github에서 새 저장소(New Repository) 생성**: 프로젝트 이름(Repository name) 등을 입력하고 저장소 생성.
2.  **저장소 주소 복사**: 생성된 저장소 페이지에서 HTTPS 주소를 복사.
3.  **로컬에 복제(Clone)**: 컴퓨터의 원하는 위치에서 터미널을 열고 아래 명령어 실행.

    ```bash
    git clone (복사한 레포지토리 주소)
    ```

### 2. '.gitignore'로 특정 파일 추적 제외하기

-   **`.gitignore` 파일 생성**: 프로젝트 최상위 폴더에 `.gitignore`라는 이름의 파일 생성.
-   **무시할 파일/폴더 등록**

    ```
    # 특정 파일 무시
    temp1.txt

    # 특정 확장자를 가진 모든 파일 무시
    *.log

    # 특정 폴더와 그 안의 모든 내용 무시
    secret_folder/
    ```


### 3. 핵심 작업 흐름: `add`, `commit`, `push`

1.  **상태 확인 (status)**
    ```bash
    git status
    ```

2.  **스테이징 (add)**
    ```bash
    # 변경된 모든 파일을 스테이징
    git add .

    # 특정 파일만 스테이징
    git add (파일 이름)
    ```

3.  **로컬 저장소에 기록 (commit)**
    ```bash
    git commit -m "Add: 로그인 기능 구현"
    ```

4.  **원격 저장소에 업로드 (push)**
    ```bash
    git push origin main
    ```

# 브랜치(Branch)란?

> 브랜치는 기존 코드에 영향을 주지 않고 독립적으로 작업을 개발하기 위한 **격리된 작업 공간**. 

-   **브랜치 생성**
    ```bash
    git branch (브랜치 이름)
    ```
-   **브랜치 전환**
    ```bash
    git switch (브랜치 이름)
    ```
-   **브랜치 병합 (Merge)**
    ```bash
    git merge (병합할 브랜치 이름)
    ```

# 커밋 기록(Log)과 HEAD

### 1. **`git log`**
현재 브랜치의 커밋 내역을 시간순으로 조회하는 명령어.
-   **커밋 해시**: 커밋을 식별하는 고유 ID.
-   **작성자 및 일시**: 커밋을 만든 사람과 시간.
-   **커밋 메시지**: 변경 사항에 대한 설명.

### 2. **`HEAD`** 
현재 내가 작업하고 있는 브랜치의 **가장 최신 커밋을 가리키는 포인터**. 
- 브랜치를 `switch`하면 `HEAD`도 해당 브랜치의 최신 커밋으로 함께 이동.

# Issue와 Pull Request

### 1.  **이슈 (Issue)**
프로젝트에서 처리해야 할 **작업 단위를 등록하고 추적**. 

  -   본격적인 코딩 전, 어떤 작업을 할 것인지 **목표를 설정**하고 담당자를 지정하여 팀원 간 진행 상황을 공유.
### 2.  **풀 리퀘스트 (Pull Request, PR)**
특정 브랜치에서 완료한 작업을 **다른 브랜치에 병합해달라고 공식적으로 요청**하는 기능.

  -   PR을 생성하면 다른 팀원들이 변경된 코드를 직접 확인하고 의견을 남기는 **코드 리뷰(Code Review)**가능.
  -   리뷰를 통해 코드 품질을 높이고 잠재적 문제를 사전에 방지.
