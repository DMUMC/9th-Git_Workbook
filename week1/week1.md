## 1. Git 이란?
- 파일의 변경 사항을 추적하고 여러 사용자 간에 해당 파일들의 작업들을 조율하기 위한 분산 버전 관리 시스템

## 2. GitHub 이란?
- Git 저장소를 온라인에서 호스팅해주는 서비스
- 협업, 코드 리뷰, 버그 관리, 오픈소스 기여 등에 활용됨

## 3. 파일 관리되는 방법  
1. **작업 디렉토리 (Working Directory)**  
   실제 파일을 수정하는 공간
2. **스테이징 영역 (Staging Area)**  
   커밋할 변경 내용을 모아두는 공간
3. **저장소 (Repository)**  
   커밋이 기록되어 버전이 관리되는 공간


## 4. 저장소
| 명령어 | 설명 |
|---|---|
| `git clone (레포지토리 주소)` | 원격 저장소를 로컬로 복제 |
| `git init` | 새로운 저장소 초기화 |

## 5. 파일 추적 & 상태 관리
| 명령어 | 설명 |
|---|---|
| `git status` | 현재 파일들의 상태 확인 |
| `git add .` | 모든 변경 파일을 Staging Area에 추가 |
| `git add (파일명)` | 특정 파일만 Staging Area에 추가 |
| `git commit -m "(메시지)"` | 변경사항을 커밋으로 기록 |
| `git push origin (브랜치명)` | 원격 저장소의 해당 브랜치에 반영 |

## 6. 브랜치 (Branch)
- 독립적인 작업 공간을 제공
- 여러 사람이 동시에 다른 기능을 개발할 수 있도록 지원
- **merge**를 통해 최종적으로 메인 브랜치에 반영  

| 명령어 | 설명 |
|---|---|
| `git branch (브랜치명)` | 새 브랜치 생성 |
| `git switch (브랜치명)` | 해당 브랜치로 전환 |
| `git merge (브랜치명)` | 다른 브랜치를 현재 브랜치에 병합 |

## 7. 로그 확인
| 명령어 | 설명 |
|---|---|
| `git log` | 커밋 기록 확인 |


## 8. 추적 방지 
- Git이 추적하지 않을 파일/폴더를 지정하는 설정 파일
- .gitignore에 파일/폴더 이름 작성
